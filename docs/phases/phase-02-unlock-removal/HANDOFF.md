## 1. 本阶段目标

1. 所有皮肤、披风、装饰不需要解锁条件，包括 `adm*` 管理员披风和签到活动款。
2. 保留皮肤预览、切换、渲染、装饰选择、披风显示、外观保存与恢复。
3. 不只隐藏锁定图标：修改真正的权限判断。
4. 多人入口不再要求登录/关注/三连/识别码；房间加入仍走邀请码/房间服务校验。
5. 不进入 phase-03，不重写无关模块。

## 2. 实际完成

### 2.1 披风（`js/capes.js`）

- `Capes.unlocked(id)` 改为只看 id 是否为已知披风，全部返回 true。
- 删除 `evOwned()` 与账号 `owned`/`super`/`Account.has('anim'|'static')` 判定。
- `Capes.of()` 不再把未解锁披风置空；本地玩家读取 `Skins.look()`（设备/账号外观）。
- 管理员款与活动款的注释更新为已开放；纹理、王冠、翅膀、粒子特效逻辑未改。

### 2.2 装饰（`js/cosmetics.js`）

- `owned()` 返回全部 8 个装饰 id；`has()` 对已知装饰为 true。
- `lookOf()` 不再按账号拥有列表过滤帽子/宠物/前缀。
- 模型、宠物跟随、前缀字体、显示设置 `cosShow` 未改。

### 2.3 皮肤与外观保存（`js/skins.js`）

- 预设皮肤页不再按 `own` 过滤：18 款全部显示。
- 正版玩家皮肤输入框不再被 `Account.has('skin')` 挡住；`Skins.lookOf()` 不再拦截 `m:` 皮肤。
- 新增 `mcjs-look` 本地存储（`skin/slim/cape/hat/pet/pre`）：
  - 无账号也可保存，保存后刷新恢复。
  - 登录后首次读取会接管一次账号外观；之后以本设备保存为准。
  - 登录状态下保存仍调用 `Account.update({skin})`；失败时保留本地保存并提示同步失败。
  - 衣柜 `dirty` 改为与保存快照比较，不再依赖账号数据。
- 衣柜构造函数不再调用 `Account.loadGate()`。

### 2.4 账号（`js/account.js`）

- 账号模块保留到 phase-03；但不再参与外观/多人权限。
- 删除登录后与每次访问时的 `Account.checkUnlocks()` 调用；方法保留给 phase-03 清理。
- 账号界面删除「三连/关注」解锁状态行；账号画面不再加载 gate。
- `Account.has()` 保留但已无外观调用点。

### 2.5 文案（`js/onboard.js`）

- 「这个版本有什么不一样」改为“全部皮肤/披风（含管理员款）/帽子/宠物/前缀已直接开放”。
- 更新内容里删除“三连 / 关注解锁”的旧说法。

### 2.6 多人游戏

- `onlineGate()` 在 phase-01 已按 1-A 直接放行；本阶段未改回、未加新门槛。
- 未登录点击「多人游戏」直接打开 `MultiplayerScreen`，不出现登录/关注界面。
- 邀请码仍在：空码不加入；输入 6–12 位码后才调用 `game.joinRoom`。
- 公开房间列表、直接连接、本地房间入口保留；房间服务端校验未改。

## 5. 关键决策

1. **管理员披风也全开放**：用户 2026-11-12 指令明确“全开放包括 adm* 管理员披风”，覆盖 ADR-011 第 3 项“管理员款保持隐藏”。见 ADR-014。
2. **外观本地保存**：无账号也能保存/恢复；账号登录时接管一次账号外观。这样“开放”不是只在本次会话有效，也为 phase-03 访客模式留出路径。
3. **账号模块保留**：phase-02 只让账号不再决定权限；删除账号/登录/云存档/签到仍属 phase-03。
4. **多人加入控制不动**：`onlineGate` 已在 phase-01 放行；邀请码/公开房间列表/房间服务校验保持原样。
5. **验收后提交**：按 ADR-009 与 PROJECT_SPEC §11.3；用户结束验收后提交代码 `a9dc47b`，未推送。
