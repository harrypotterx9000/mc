## 1. 本阶段目标

在不依赖 Bilibili/Toy 或任何外部游戏平台的前提下，让 OpusMC 的多人世界运行在项目所有者自己的
Windows 电脑上：

1. 同一进程提供网页静态资源、房间服务、WebSocket 通信、临时玩家 ID、邀请码、多人世界、状态同步、
   服务端存档、备份、状态监测、日志与正常启动/关闭。
2. 客户端只负责 WebGL2 渲染、摄像机、UI、输入、本地画面/动画与合理的本地预测；服务器不渲染画面。
3. 优先复用原有客户端的协议词汇与区块/方块记录方式；`NetClient`（原版 Java 代理直连）保留为遗留功能。
4. 房间有创建/加入/退出/关闭/人数上限/房主权限；邀请码由服务器生成，不可简单猜测；加入有限流。
5. 同步玩家位置/视角/状态/外观、方块变化、实体状态、世界时间、进入/离开、断线恢复、状态快照与增量。
6. 服务端做基本权威校验：房间成员、权限、方块交互、移动异常、协议结构；不信任客户端权限标识。
7. 数据目录在静态根之外；管理接口不暴露给普通玩家；输入与 WebSocket 消息校验；异常连接处理。
8. Windows 一键启动、配置、正常关闭、日志、世界目录、自动保存、运行状态、异常恢复说明；明确
   电脑关机/休眠时服务器不可用。

## 2. 技术选择（依据 phase-00 结论）

- **运行环境**：本机 Node.js v26.13.0，仓库原无 `package.json`。phase-00 已确认世界生成模块可在 Node
  加载，但 `game.js` 的 `init/tick/render` 贯穿 DOM/Canvas/WebGL/UI，直接跑完整无头游戏风险高。
- **不引入 `ws`，也不新增 npm 依赖**：用 Node 内置 `http` + `crypto` + 自写 RFC 6455 服务端，
  保持“解压即可运行、无需 npm install”的一键启动；浏览器客户端使用标准 `WebSocket`。
- **权威边界（B/C 混合的落地）**：
  - 服务器权威：房间生命周期、临时身份、邀请码、权限、世界种子/出生点/时间、方块覆盖层、方块实体、
    玩家实体状态、掉落物实体、加入/离开/断线、存档。
  - 客户端本地：WebGL2 渲染、摄像机、UI、输入、地形确定性生成（同一 seed）、生物 AI、玩家物理、
    背包/生命等本地玩法与动画、合理的本地预测。
  - 服务器不保存/传输完整 98,304 格地形，只保存“相对确定性地形的增量”；客户端用服务器 seed 生成地形，
    再应用服务器增量。这样服务器保持权威且内存/存档可控。
  - **本阶段不同步生物实体**（每个客户端本地模拟）；同步的实体是玩家与服务器管理的掉落物。此边界
    在 `KNOWN_ISSUES` 与交接中明确记录，不写成完整服务端模拟。
- **协议**：WebSocket 上的 JSON 消息；复用 `p2p.js` 的词汇（`welcome`/`state`/`pstate`/`b`/`be`/`E`/
  `env`/`chat`/`give`/`drop`/`pickup`）与方块记录思路，但传输、身份、权限、校验、存档由服务器实现。
  不使用 `NetClient` 的原版 Java 代理协议。

## 3. 服务端结构

```
server/
  index.mjs        入口：配置、HTTP、WS、房间管理器、tick、信号与正常关闭
  config.mjs       读取/校验 server/config.json，解析相对路径
  log.mjs          JSONL 日志（按日文件 + 控制台），保留天数
  storage.mjs      数据目录、原子写入、房间加载、备份/保留、损坏回退
  blockids.mjs     从 js/blockdata.js + js/blocks.js 读取合法方块 ID
  ws.mjs           零依赖 RFC 6455 服务端（掩码/分片/ping/pong/close/限额/心跳）
  protocol.mjs     消息结构、字段范围、昵称/房间名/聊天清洗、协议限额
  rooms.mjs        RoomManager + Room：权限、邀请码、身份、限流、快照、tick
  http.mjs         静态白名单、ETag/304、缓存、/healthz、/api/status、本机管理接口
  config.json      默认配置（无密钥；管理令牌首次运行生成到 data/）
  README.md        Windows 部署/配置/存档/备份/安全/排查说明
  stop.ps1         正常关闭脚本实现（支持 -Config）
  status.ps1       查看运行状态（支持 -Config）
  data/            运行期生成（gitignore）：日志、世界、备份、pid、管理令牌
根目录
  start-server.bat 一键启动
  stop-server.bat  正常关闭（调用本机管理接口，失败才提示强制结束）
```

## 4. 房间与身份规则

- 邀请码：8 位，字符集去除易混字符（`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`），由
  `crypto.randomInt` 生成；服务器保证当前/已存档房间内唯一；不提供公开房间列表（仅凭邀请码加入）。
- 临时玩家 ID：`p_` + 16 位十六进制，服务器签发；昵称不是身份，不参与权限判断；重名由服务器追加
  `2..99` 消歧。
- 会话令牌：服务器为每次加入签发随机令牌，客户端只保存在本标签页 `sessionStorage`；服务端只保存
  SHA-256。断线/刷新后可在 120 秒内 `resume`，恢复实体与最近一次 `pstate`；令牌不写入日志、不属于账号。
- 房主：创建者；房主主动离开时，房主自动转给最早加入的其他玩家；房间已空则保留为“无房主”，
  下一位加入者成为房主。房主可踢人、关闭房间；普通玩家不可。
- 关闭房间：只允许房主；广播 `closed`，保存世界并标记 `closed=true`，邀请码不再可用。
- 人数：每房 2–10 人（服务器上限 10，可配置）；满员拒绝加入。
- 限流：按 IP 的加入/创建令牌桶；按连接的总体消息、方块、聊天、方块实体、掉落/拾取令牌桶；
  超限返回错误或丢弃，不崩溃。
- 一个 IP 可开多个标签页调试，但受连接上限与房间上限约束。

## 5. 世界与同步

- 世界元数据：`seed`（int32）、`gen=2`、`spawn`、`time`、`weather`、`rain`、`difficulty`、`gamemode`。
  创建房间时客户端按 seed 计算安全出生点并提交，服务器校验范围后作为权威值保存。
- 方块覆盖层：按区块分组保存 `[x,y,z,id,meta,wl]`；服务器接受后立即广播（含发送者）并计入存档；
  上限 `maxBlocksPerRoom`（默认 100000）。客户端收到后：区块已加载则立即 `setBlock`，未加载则缓存，
  区块生成完成时应用。
- 方块实体：`k` 必须为 `x,y,z`，值为 JSON（≤4 KB），服务器保存并广播最后写入；上限 5000。
- 玩家状态：10 Hz `state`（位置/视角/潜行/挥手/手持/盔甲/模式/飞行/游泳/外观/生命）；
  10 秒一次 `pstate`（位置、生命、饥饿、经验、背包、模式、外观）用于服务器存档与恢复。
  服务器以 10 Hz 快照广播玩家与掉落物，客户端用 `NetPlayer`/`netItemTick` 插值。
- 世界时间：服务器 20 TPS 递增，每 40 tick 广播；客户端本地平滑推进并在偏差过大时校正。
- 进入/离开/断线：广播 `players`/`join`/`leave`；断线保留 120 秒恢复窗口，超时后从在线列表移除。
- 增量：正常游戏只发方块变化、实体快照、环境/时间、聊天；加入时发一次完整增量（`welcome` +
  `blocks` 分批 + `ready`）。

## 6. 服务端校验（基本权威）

- 消息必须是 JSON 对象、`t` 已知、字段类型/范围正确；超出大小或连续错误关闭连接。
- 只有已加入房间的连接可发游戏消息；玩家 ID 只能来自服务器；忽略客户端传来的 `owner`/`admin`/
  `permission` 字段。
- 方块：坐标/ID/meta 范围、Y 界、与服务器记录的最后位置距离（生存 7 格，创造 10 格，含 3 格延迟容差）、
  每连接每秒上限；越界/超距拒绝并让客户端重载该区块。
- 移动：水平 ≤20 m/s、垂直 ≤30 m/s，单次更新加 3 格容差；超速不接受并下发 `correct`；
  死亡重生/跨维度/超时断开时重置基准。
- 掉落/拾取：堆栈结构与数量、距离、拾取延迟、每房物品上限。
- 方块实体/聊天/昵称/房间名：清洗控制字符与长度；聊天 1 条/秒（突发 3）。
- 管理接口：仅本机回环 + 管理令牌；普通玩家不可达。
- 不要求本阶段实现复杂反作弊；以上为基本状态管理与操作校验。

## 8. 启动、备份与恢复

- 根目录 `start-server.bat`：`node server\index.mjs`；默认 `127.0.0.1:8080`，与静态页面同源。
- 根目录 `stop-server.bat` → `server/stop.ps1`：POST 本机 `/api/admin/shutdown`（带 `data/admin-token.txt` 令牌）；
  超时未退出才提示手动结束进程。
- `server/status.ps1`：输出 `/healthz` 与（本机）管理状态。
- 自动保存：默认 60 秒 + 房间关闭 + 正常关闭；原子写入 `worlds/<dir>/world.json`。
- 备份：保存前按间隔复制到 `backups/<dir>/<时间>.json`，保留最近 10 份；启动读取失败时回退最新备份。
- 日志：`data/logs/server-YYYY-MM-DD.log`（JSONL），保留 14 天；不记录会话令牌。
- 电脑关机/休眠/注销时服务器停止，无法提供服务；部署文档明确，不承诺后台常驻。
- 默认只绑定 `127.0.0.1`；局域网联机需把 `host` 改为 `0.0.0.0` 并在防火墙放行，属 phase-08 部署范围，
  本阶段只做可用性与说明，不宣称公网/HTTPS/NAT 已完成。

## 9. 测试计划

1. 静态与安全：白名单/404/404 数据目录/ETag/304/HEAD/缓存头/安全头；`/healthz`。
2. 协议与房间：创建、加入、重名消歧、满员、无效邀请码、非房主踢人/关房、房主踢人/转让/关房、
   离开、断线恢复、令牌错误、协议版本/结构错误、超限。
3. 同步：玩家状态快照、方块增量（发送者/其他玩家/后加入）、方块实体、时间、聊天、掉落/拾取。
4. 权威：超距方块拒绝、超速移动纠正、越界/非法字段拒绝、客户端伪造 owner 无效。
5. 安全：加入限流、消息限流、超大消息/二进制帧、异常连接、管理接口无令牌（非本机拒绝未双机验证）。
6. 持久化：自动保存、房间重开、重启恢复、关闭房间、备份生成与损坏回退、正常关闭。
7. 浏览器 E2E：两个独立浏览器配置创建/加入、互看玩家、移动、方块、聊天、踢人/关房、重连；
   `game.errLog` 与未捕获异常为空。
8. 静态：全部 `js/*.js` `node --check`、`git diff --check`、JS/mjs/md 无 BOM；`.ps1` 为兼容 Windows
   PowerShell 5.1 的中文使用 UTF-8 BOM。

## 10. 明确不做

- 不做账号、注册、登录、密码、永久身份或身份数据库。
- 不把 DOM/Canvas/Renderer/UI 搬进服务器；不在服务器生成/传输游戏画面。
- 不实现服务端生物 AI、完整地形模拟、红石/战斗/物品语义的完整权威（本阶段边界见第 2 节）。
- 不做公网、HTTPS/WSS、NAT 穿透、反向代理、PWA；不做 phase-06 双存档管理界面。
- 不重写单人玩法、渲染、世界生成、红石、战斗等无关模块。
