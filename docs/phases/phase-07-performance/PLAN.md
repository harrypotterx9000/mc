## 2. 基线（headless Chrome 157 + 真实 ANGLE D3D11，AMD Radeon 核显；1280×720；maxFps=60）

已观察到的基线问题：
- 每次方块编辑 `flushMesh()` 最多同步重网格 5×5 个区块，主线程区块网格耗时约 14 ms/个；在区块边界编辑会叠加成可见卡顿。
- `chunkWatchdog()` 只看同一 7×7 缺失区块持续 8 s；CPU 慢但仍在推进时也会误报 `chunk stall`，并删除 pending 任务重新请求（K-39 的环境条件）。
- 低/中画质没有按画质档限制远距离实体、地面阴影和粒子；大量实体场景 draw call 约 2600。
- 动态分辨率第一步只降 10%，且手机下限 50%；高像素手机从满分辨率降到可用档位需要多个 1.5 s 窗口。
- 服务器没有 TPS/tick 耗时/CPU/内存观测；广播对每个连接重复 `JSON.stringify`。

## 3. 实施项

### 3.1 测试基线
- 固定 profile + 固定世界（普通地形、大型建筑）复测；场景：主菜单、普通地形、大型建筑、大量实体、战斗、多人房间、长时间运行。
- 记录 FPS、平均/p50/p95/p99/最慢帧、JS 堆、GPU timer、draw call、buffer 上传、区块生成/装饰/完成/网格耗时、网络 RTT/流量、服务器 TPS/CPU/RSS。

### 3.2 电脑端
- 保持 60 目标；验证光影 0–4 档；保留渲染距离 2–16 与自定义。
- 视频设置增加“测试性能并推荐画质…”：在实时画面测量帧时间/GPU 耗时，按实际结果推荐并应用。
- 首次进入仍由 `QualityScreen` 实测推荐；旧设置文件玩家获得一次基于实际帧时间的提示（不强制修改）。
- 减少编辑时同步重网格的卡顿；复用渲染可见列表，降低每帧分配。

### 3.3 手机端
- 动态分辨率：手机下限 40%，首次降档 20%，保持防抖动逻辑。
- 区块预算：手机主线程区块工作上限 8 ms（桌面 12 ms），减少帧内长任务。
- 实体/阴影/粒子预算：低/中档限制远距离实体与地面阴影，粒子上限 1200/2000；高档保留全集。
- GPU 显存：手机地形顶点页 4 MB（桌面 8 MB），仍使用 arena 合并/压缩。
- 触控：不改变事件路径；用移动视口模拟测帧时间与动态分辨率恢复（真机仍 NOT TESTED）。

### 3.4 画质分级
- 保留低/中/高/极高和自定义；视频设置轮换包含“自定义”，单项修改仍自动切自定义。
- 推荐依据：实测 FPS + p95 + GPU 时间；硬件型号只用于初始猜测。
- 自定义不强制覆盖玩家值。

### 3.5 服务器
- 增加滚动 TPS、tick 平均/最大耗时、迟到 tick、CPU%、RSS/heap；只通过管理接口暴露。
- 房间广播一次编码、多连接复用，降低多玩家 CPU。
- 压测 2/5/10 人单房、10 人×3 房，带方块编辑、聊天、ping；如实记录是否达到 20 TPS。

### 3.6 K-39
- 由“同一 7×7 缺失 8 s”改为“缺失且无任何区块/生成/完成/网格进展，或缺失项 8 s 无归属”；生成仍推进时不再误报/删除任务。
- 用 headless SwiftShader + CPU 限速复现；修复后要求不再出现 `chunk stall`，世界仍进入 play。
