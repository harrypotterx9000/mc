## 2. 环境与方法

- 主机：Windows 10/11，Node.js v26.13.0，Chrome 157.0.8103.51 headless。
- 桌面 GPU：`ANGLE (AMD, AMD Radeon(TM) Graphics (0x00001638) Direct3D11 vs_5_0 ps_5_0, D3D11)`；
  `EXT_disjoint_timer_query_webgl2` 可用。
- 固定 profile + 两个固定世界：`phase07 normal`（种子 12345）与 `phase07 building`（种子 777）。
  同一相机/实体生成；测量前清除上次自动保存的动物，并把 `game.lastSave` 置为不触发自动保存，

- 每场景 8 秒；基线 = HEAD `ea88dba` 归档副本，优化 = phase-07 工作区；同一 profile/世界/相机。
- 手机模拟：Android/Pixel 8 Pro UA，视口 1560×720 CSS、DPR 2 → canvas 3120×1440；**GPU 仍是桌面
  AMD 核显**，只能验证像素负载与移动端预算，不能代表真实手机。

  光影关；创建→保存→刷新→载入同一世界，两轮。

## 6. K-39（SwiftShader + CPU 8×）

`_work/k39-check.mjs`：Chrome headless + SwiftShader，`Emulation.setCPUThrottlingRate=8`，两轮
创建→保存→刷新→载入。

| 版本 | 载入 0 | 刷新 0 | 刷新 1 | `chunk stall` |
|---|---:|---:|---:|---:|
| 基线 | 8.1 s | **46.6 s** | **46.9 s** | **3** |
| 优化 | 9.7 s | 8.8 s | 8.7 s | **0** |

- 基线 watchdog 在同一 7×7 缺失 8 s 后删除 pending/重新请求，反而把载入拖到 46 s；优化在仍有生成/装饰/
  完成/网格进展、或有 `savedFetch` 存档读取、或管线仍忙时等待，只在“缺失 + 管线空闲 + 无进展”时重请求。
- 修复后世界仍进入 play，方块/区块读取正常，零 `chunk stall`。
- 这是 SwiftShader + CPU 限速条件；真实手机/真实网络未测。

## 12. 独立验收修复（2026-11-13）

验收发现并修复了 3 个问题；修复后重新做了针对性实测：

| 问题 | 修复 | 修复后实测 |
|---|---|---|
| 动态分辨率目标在 90 Hz / 无限制 / 30 Hz 场景错误 | `DynRes.target()` 使用 `Math.max(display interval, 60 fps)`；VSync 关闭且无帧率限制时固定 60 目标；显式 `maxFps` 仍优先 | 90 Hz → 16.67 ms；30 Hz → 33.33 ms；无限制 → 16.67 ms；`maxFps=30` → 33.33 ms；`maxFps=120` → 8.33 ms |
| 粒子满额时 `ambientParticles()` 抛 `TypeError` | 火焰/烟雾两处先取返回值并判空；满额时只跳过该粒子 | `low` 预设 `particles.max=1200`，填满 1200 后再触发火把环境粒子：无异常，长度保持 1200 |
| 画质建议忽略玩家 `maxFps` 上限 | `PerfMon.recommend()` 的 target 改为 `min(画质目标, pacer.limit)`（无上限时保持 60/30 目标） | `maxFps=30` 时 target=30、不再建议降档；`maxFps=60` 且实测 30 FPS 时仍正确建议 medium |
