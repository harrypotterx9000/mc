# 局域网部署（模式 A）

适用：一台 Windows 电脑当服务器，手机和电脑在**同一个 Wi-Fi**。
不需要公网 IP、域名、HTTPS 或端口转发。

> 目标：所有设备（**包括这台电脑自己**）都打开同一个
> `http://<电脑局域网IP>:8080/`，这样邀请链接、WebSocket 和房间地址才一致。

## 1. 准备

- Windows 10/11。
- Node.js 20 或更新：命令行运行 `node --version` 能看到版本号。
- 所有设备连接同一个 Wi-Fi；不要用“访客网络”，也不要让手机走移动数据。
- 建议路由器为这台电脑保留固定 IP（DHCP 保留），否则重启后 IP 可能变化。

## 2. 找到这台电脑的局域网 IP

```powershell
ipconfig
```

看“无线局域网适配器 WLAN”下的 **IPv4 地址**，例如：

```
IPv4 地址 . . . . . . . . . . . . : 192.168.1.18
```

也可以启动服务器后直接看它打印的“游戏地址（局域网）”。

## 3. 启动服务器（局域网模式）

双击项目根目录的 **`start-lan.bat`**，或在项目目录运行：

```powershell
node server\index.mjs --lan
```

启动成功会看到：

```
OpusMC 自建服务器已启动
游戏地址（局域网）：http://192.168.1.18:8080/
仅本机访问（服务器电脑）：http://127.0.0.1:8080/
```

- `start-lan.bat` / `--lan` 会把服务器绑定到 `0.0.0.0`，手机才能访问。
- **`游戏地址（局域网）` 是主地址**；`127.0.0.1` 只用于服务器电脑本机，不能用来生成/分享邀请链接。
  如果打印了多个局域网地址，优先使用 Wi-Fi 的那个。
- 原来的 `start-server.bat` 仍然只绑定 `127.0.0.1`（只有本机能访问），
  这是安全的默认值；局域网联机请用 `start-lan.bat`。
- 服务器窗口要一直开着。关窗口、关机、休眠、注销后服务器停止，多人世界不可用。
- 端口默认 8080；被占用时改 `server/config.json` 的 `port`，再重启。

## 4. Windows 防火墙（首次必须）

第一次启动 Node 时，Windows 可能弹出“允许 Node.js 访问网络”：

- 勾选 **专用网络**，点“允许访问”。
- 不要勾选“公用网络”（除非你明确知道这是可信的家庭网络）。

如果没弹窗、已经点过“取消”，用**管理员** PowerShell 在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\firewall-lan.ps1 -Port 8080
```

脚本只放行 **TCP 8080 的专用网络入站**，不会开放其他端口。
撤销：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\firewall-lan.ps1 -Remove
```

注意：

- 用 `Get-NetConnectionProfile` 查看 Wi-Fi 是“专用/Private”还是“公用/Public”。
  如果家里 Wi-Fi 被 Windows 标成 Public，脚本默认**不会**放行；可以把该网络改成专用，
  或明确加 `-IncludePublic`（只在家里可信 Wi-Fi 用，绝不要在咖啡厅/机场/酒店用）。
- 如果手机还是打不开，先按第 8 节排查 AP 隔离/访客网络。

## 5. 所有设备打开同一个地址

在**电脑、手机、平板**的浏览器里都打开启动时打印的那个地址，例如：

```
http://192.168.1.18:8080/
```

- 电脑自己**也不要**打开 `http://127.0.0.1:8080/`。用 `127.0.0.1` 打开时，
  页面生成的邀请链接会是 `127.0.0.1`，发给手机后打不开。
- 每台设备打开同一地址后，客户端会自动用同源的 `ws://192.168.1.18:8080/ws`。
- 验证（手机浏览器直接打开）：

```
http://192.168.1.18:8080/healthz
```

返回一段 JSON（`"ok":true`）就说明网络和防火墙已通。

## 6. 创建和加入房间

1. 打开页面 → **多人游戏** → 输入昵称。
2. **自建服务器房间（本机 / 局域网）…** → **创建房间**。
3. 选择房间人数、模式、难度 → **创建并进入**。
4. 把 8 位邀请码发给同一 Wi-Fi 的人；对方在同一页面输入邀请码 → **加入**。
5. 也可以点 **复制邀请链接**，链接形如：

```
http://192.168.1.18:8080/?room=ABCD2345&server=1
```

所有玩家进入的是同一个服务器世界（同一个 `seed` + 服务器方块覆盖层）；
玩家位置、方块改动、方块实体、掉落物、世界时间由服务器同步。

限制（默认，可在 `server/config.json` 调整）：

- 同时最多 8 个房间，单房 2–10 人，最多 64 个连接。
- 加入/创建按 IP 限流；同一 Wi-Fi 的玩家共享出口 IP，人多时可能触发限流，
  可调大 `joinPerMinute` / `joinBurst` / `createPerMinute` / `createBurst`。

## 7. 验证清单

- [ ] 手机打开 `http://<IP>:8080/healthz` 返回 `ok:true`。
- [ ] 两台设备打开同一地址，分别输入昵称。
- [ ] A 创建房间，B 用邀请码加入；双方房间人数显示 2。
- [ ] A 放置/破坏方块，B 能看到；B 移动，A 能看到。
- [ ] 聊天双方可见。
- [ ] 服务器窗口日志出现 `room_created`、`room_joined`、`ws_open`。
- [ ] 关闭页面再打开，120 秒内可凭本标签页会话恢复到原房间（同一浏览器标签页）。

## 8. 常见问题

**手机打不开页面**

- 手机和电脑是否在同一 Wi-Fi？访客网络/不同 SSID/不同频段可能互相隔离。
- 路由器是否开启了 **AP 隔离 / 客户端隔离**？开启后设备之间不能互访，需要关闭。
- Windows 防火墙：网络是不是 Public？先用第 4 节脚本；仍不行可临时关闭专用网络防火墙测试
  （测试后恢复，不要长期关闭）。
- 电脑是否有 VPN/虚拟网卡？启动打印了多个地址，选 Wi-Fi 的那个。
- IP 是否变了？重新 `ipconfig` 或看启动输出。
- 用手机浏览器打开 `http://<IP>:8080/healthz`；如果超时，是网络/防火墙问题，不是游戏问题。

**能打开页面但建房/加入失败**

- 看服务器窗口有没有报错；确认服务器还在运行。
- 确认页面地址和邀请链接是同一个 IP，不是 `127.0.0.1`。
- 端口被占用时换 `port`。
- 服务器日志：`server/data/logs/server-YYYY-MM-DD.log`。

**邀请链接是 127.0.0.1**

电脑用 `127.0.0.1` 打开了页面。改用 `http://<局域网IP>:8080/` 重新打开/复制。

**很卡 / 延迟高**

- Wi-Fi 信号、2.4G 拥塞、距离、电脑同时下载/上传。
- 服务器只做逻辑同步，不做画面渲染；卡顿也可能来自客户端 GPU。
- 局域网正常延迟通常是个位数毫秒；不承诺具体数值。

**关闭服务器**

双击 `stop-server.bat` 或服务器窗口 `Ctrl+C`。服务器会保存所有房间、写备份、删除 pid 后再退出。
不要直接关机/强制结束进程；关机/休眠时多人世界不可用。

## 9. 数据与安全边界

- 服务器世界在 `server/data/worlds/room-<邀请码>/world.json`，**不在网页目录**，
  不会通过 HTTP 提供；不要手动删除，备份在 `server/data/backups/`。
- 单人世界仍在浏览器 IndexedDB（`mc-js-clone`），与服务器世界互不写入。
- 局域网是 **HTTP 明文**：同一 Wi-Fi 下的人理论上可以嗅探邀请码/会话令牌。
  只在家里可信 Wi-Fi 使用；不要在公司/公共 Wi-Fi 开 `-IncludePublic`。
- 管理接口（`/api/admin/*`）只允许本机回环 + 管理令牌；从手机/LAN IP 访问会得到 403。
- 不要把 8080 端口转发到公网；公网访问请用 HTTPS/WSS，见
  [`REMOTE.md`](REMOTE.md)。

## 10. 本阶段实测与未测

实测（2026-11-13，Windows + Node 26，Chrome 157 两个独立 profile）：

- LAN 模式启动输出主地址为 `http://192.168.1.18:18110/`，`127.0.0.1` 单独标为“仅本机访问”；
- 本机经 LAN 地址打开页面、`/healthz`、WebSocket；
- 两个独立浏览器从同一个 LAN 地址创建/加入房间，同一 seed，方块/聊天/玩家同步；
- 多次建房、加入、刷新/恢复后邀请链接仍使用 LAN 地址（专项 8/8）；
- LAN 地址访问管理接口 403，本机回环 + 令牌 200；
- `/server/data`、`/docs`、`/scripts`、`/.git` 经 LAN 地址不可访问。

**真实手机 LAN（用户报告 2026-11-14）**：手机在同一 Wi-Fi 下完成单人游戏、移动、转视角、放置、破坏、
刷新重进，并作为第二客户端加入 LAN 房间；服务器日志显示 `E7UDCMQT` 房间有 LAN 私有地址客户端加入
（电脑侧 `192.168.1.18`，手机侧 `192.168.1.9`），2 名玩家。用户未提供手机型号/OS/浏览器/截图/录屏。

**NOT TESTED**：

- Windows 防火墙规则的实际添加/删除（当前测试会话非管理员，网络为 Public；手机 LAN 实测说明当前
  系统已有的 `node.exe` Public 入站规则可用）。
- 真实手机性能、发热、电池、长时间运行。
- 路由器 DHCP 保留/固定 IP 的实际配置。
- Caddy/公网部分见 `REMOTE.md`；不属于 LAN 测试。
