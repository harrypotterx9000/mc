# 技术决策记录（DECISIONS）

> 每条决策只增不改；被推翻时新增一条并注明取代关系。

## ADR-001 独立静态站点运行

- 日期：2026-11-06
- 决策：项目以静态站点方式运行（`index.html` + `js/`），本地用零依赖 Node 静态服务器，仅绑定 `127.0.0.1`。
- 理由：原游戏即 90 个脚本 + 数据文件，无构建步骤；静态服务满足 Worker/`fetch` 的同源要求。
- 影响：后续服务器只承担多人逻辑，不负责页面托管（可由同一进程提供，但不是必须）。

## ADR-002 移除 B 站重定向，保留原始版本标签

- 日期：2026-11-06
- 决策：为了让页面能在 B 站 iframe 之外启动，删除 `index.html` 中唯一一行 Toy 重定向脚本；其余字节不变。
- 理由：该脚本会把任何直接访问跳回 bilibili.com，导致本地不可用。
- 保护：删除前的完整源码提交为 `v0.0.0-original`，并另有 zip + SHA-256 清单。
- 影响：这是初始化阶段唯一的源码改动，已在 CHANGELOG 记录。

## ADR-003 无账号访客模式

- 日期：2026-11-06
- 决策：删除 B 站登录与账号体系；玩家用昵称 + 服务器分配的临时 ID；用邀请码进房间；不建任何注册/登录。
- 理由：见 PROJECT_SPEC §3/§6；避免永久身份带来的隐私与合规负担。
- 影响：云存档（按账号）取消；皮肤/披风改为直接开放；联机不再有解锁门槛。

## ADR-004 服务器权威 + 双存档

- 日期：2026-11-06
- 决策：多人世界由自建服务器模拟与存档；单人世界继续用浏览器 IndexedDB；两者互不覆盖。
- 理由：多人需要一致性与反作弊；单人应离线可玩。
- 影响：需要新增服务器世界实例与协议；客户端 `NetClient` 复用现有消息词汇。

## ADR-005 Git 导入与分支模型

- 日期：2026-11-06
- 决策：`main` 稳定、`develop` 集成、`phase/*` 阶段分支；初始化基线打 `v0.1.0-preproject`；原始源码打 `v0.0.0-original`。
- 理由：阶段化开发需要可回滚的清晰历史；原始版本必须可随时对照。
- 影响：合并需要用户确认；禁止强推与历史重写。

## ADR-006 按字节保存源码

- 日期：2026-11-06
- 决策：仓库设置 `core.autocrlf=false` 并加 `.gitattributes`（`* -text`）。
- 理由：原始 JS 为 LF；Windows 默认转换会让"原始字节"无法验证。
- 验证：`v0.0.0-original` 的 blob 与原文件 SHA-256 一致。

## ADR-007 远程仓库以远程现状为准

- 日期：2026-11-06
- 决策：`https://github.com/harrypotterx9000/mc` 当前只有 1 个 README 提交，与本地历史无关；首次推送采用**新分支 + PR**，不改远程 `main`，不允许强推。
- 理由：避免覆盖远程内容或制造不可逆历史。
- 状态：已执行（见 ADR-008）。

## ADR-008 首次远程推送采用新分支 + PR

- 日期：2026-11-06
- 背景：本地历史与远程 `main` 无共同祖先（远程仅 `6c476c0` README）。
- 决策：`git push -u origin main:opusmc-init`，远程新增 `opusmc-init` 分支；PR 由用户在 GitHub 上创建并合并；远程 `main` 在合并前保持不变。
- 结果：`opusmc-init` 已推送（`791d16b`），远程 `main` 仍为 `6c476c0`；GCM 已有可用凭据，未出现交互弹窗。
- 影响：本地 `main` 跟踪 `origin/opusmc-init`；PR 合并后需把 `origin/main` 拉回并重新对齐跟踪关系。


## ADR-009 未验收改动不保留

- 日期：2026-11-06
- 决策：阶段改动只有在用户明确验收通过后才提交；未验收的代码、文档、暂存区、stash、补丁与临时分支一律丢弃，不跨阶段保留。
- 背景：phase-01 的改动在用户指示"先不要开始阶段 1"后被整体丢弃（stash/补丁/临时目录/阶段分支全部删除）。
- 影响：后续阶段必须"实现 → 用户验收 → 提交"；不得用 stash 长期保存半成品。

## ADR-012 阶段 1 主菜单删减的实施边界

- 日期：2026-11-06
- 背景：用户启动 phase-01，要求删除首启两屏、公告面板、解锁披风/联机面板、选项三项、主菜单指定文字与反馈面板；同时要求不切换 Git 分支、不扩大范围。
- 决策：
  1. 首启两屏整体删除：`AgreementScreen`/`LEGAL`/`legalV` 与 `PlayerKindScreen`/`PLAYER_KINDS`/`playerKind` 不再保留；首启从画质设置开始。删除两屏后首启在 50 ms 内自动打开画质基准，会在标题世界尚未建好时做 `readPixels`；改为等待 `titleWorldReady()`（最多 8 s）后再打开，避免 SwiftShader/低端设备卡死。
  2. 新世界默认关教程（`meta.tutorial ?? -1`）；旧存档 `meta.tutorial` 保留。删除玩家类型后，小地图/死亡点默认改为仅显式开启时显示；情景提示 `settings.tips` 的值不受影响。
  3. 公告模块整体删除 `js/news.js`；签到与聊天里的管理员全服公告保留；签到按钮改用标题右上角固定位置。浏览器里旧的 `mcjs-news*` 键作为死数据保留，不自动删除。
  4. 删除 `UnlockScreen` 与所有入口（标题、账号、衣柜、锁定披风），并按 1-A 让 `onlineGate()` 直接放行；皮肤/披风的内部解锁数据保留到阶段 2 再统一开放。
  5. 选项「遥测数据」与 `TelemetryScreen` 删除；`Telemetry` 核心与 `GAME_BUILD` 按 ADR-011 暂留，因此阶段 1 没有 UI 关闭入口，记录为 K-27，阶段 3 随账号/原服务整体移除。
  6. 反馈整体删除：`FeedbackScreen`/`postFeedback`/`feedbackShot`/`FEEDBACK_KINDS` 与三处入口；`social.js` 的内容检查只保留 `ReportScreen`。举报功能保留。
  7. 主菜单指定文字删除；`OpusMC` 品牌字样保留。`index.html` 头部 Toy 性能上报内联脚本一并删除（阶段 0 的 K-03）。
  8. 本次按用户指令留在 `develop` 工作区，不创建/切换阶段分支、不提交；验收通过后再提交，验收不通过则按 ADR-009/§11.3 丢弃。
- 影响：
  - 阶段 2 仍需开放皮肤/披风/装饰，并处理管理员款与活动款时序。
  - 阶段 1 中未解锁的非活动款披风/正版皮肤暂时没有解锁路径（阶段 2 开放）。
  - 阶段 3 仍需删除账号、云存档、登录、公告接口、签到与 Toy（遥测已由 ADR-013 移除）。
  - 旧设置里的 `playerKind`/`legalV` 不再读取，保留为死数据。
- 状态：**已实施，独立验收通过；代码提交 `15154bd`**。
  > 注：第 5 项“保留 Telemetry 核心”已被 ADR-013 取代（K-27，2026-11-06）。

## ADR-014 phase-02 外观全开放与保存迁移

- 日期：2026-11-12
- 背景：用户启动 phase-02，明确要求“所有皮肤、披风和装饰不需要任何解锁条件（全开放包括 adm* 管理员披风）”，保留预览/切换/渲染/装饰选择/披风显示/保存恢复；多人入口不再要求登录/关注/三连/识别码，但房间仍需邀请码控制。用户同时要求不切换分支、不提前进入 phase-03、不扩大范围。
- 决策：
  1. **全部披风开放，包括管理员款**：`Capes.unlocked()` 只校验 id 已知；删除 `evOwned`、`Account.data.super`、`Account.has('anim'/'static')` 判定。本项**取代 ADR-011 第 3 项**（原“管理员款 adm* 保持隐藏”）与第 4 项中“活动款随活动删除”的当前阶段口径；活动款在 phase-02 直接可穿戴。
  2. **全部装饰开放**：`Cosmetics.owned()` 返回全部 id，`has()` 对已知 id 为 true，`lookOf()` 不再按账号拥有列表过滤帽子/宠物/前缀。
  3. **皮肤开放**：预设皮肤取消 `own` 过滤；正版玩家皮肤取消 `Account.has('skin')` 门槛；`Skins.lookOf()` 不再拦截 `m:`。
  4. **外观保存迁移到设备**：新增 `mcjs-look`（skin/slim/cape/hat/pet/pre）。无账号可保存并刷新恢复；登录时接管一次账号外观；有账号时保存仍同步 `Account.update({skin})`，失败保留本地。衣柜 `dirty` 用保存快照，不依赖账号。
  5. **账号模块保留但退出权限链**：删除登录后/每次访问的 `Account.checkUnlocks()` 调用；账号界面不再显示三连/关注状态与 gate；`Account.has()` 不再被外观调用。账号、登录、识别码、云存档、签到、Toy 的删除仍属 phase-03。
  6. **多人保持 1-A**：`onlineGate()` 直接放行；不在本阶段新增/修改房间协议、邀请码、公开房间列表或房间服务校验。
  7. **流程**：按用户约束留在 `develop` 工作区，不新建/切换/重置分支、不提交、不推送；验收通过后再提交。
- 影响：
  - `Capes`、`Cosmetics`、`Skins` 的账号拥有/解锁判断全部移除；只保留 id 有效性校验。
  - 新增 `mcjs-look`；旧账号 `data.skin` 仍兼容（登录时接管一次）。
  - 原房间服务可能仍按 `adm*` 校验或返回 403；客户端已开放，服务端问题留 phase-05。
  - phase-03 删除账号时需保留 `mcjs-look`，否则访客外观会丢失。
  - 活动款装饰在 phase-03 是否随签到删除需用户确认；当前全部开放。
- 验证：92 个 JS `node --check`；无头 Edge 27/27 自动检查通过；18 皮肤 + 23 披风（13 管理员 + 3 活动）+ 3 帽子 + 1 宠物 + 1 前缀全部可点/预览/渲染；游客保存刷新恢复；多人入口无登录门槛且邀请码控制保留；`game.errLog` 为空。详见 `docs/phases/phase-02-unlock-removal/TEST_REPORT.md`。
- 状态：**已实施、已测试、验收结束、已提交 `a9dc47b`；docs 收尾为当前 HEAD**。

## ADR-015 phase-03 彻底移除账号系统与访客身份

- 日期：2026-11-12
- 背景：用户启动 phase-03，明确要求彻底移除账号系统（`js_account.js`/`Account`、Bilibili 登录、Toy 身份、B 站 UID、关注/三连、解锁判断、账号 API/界面/绑定、账号云存档、相关资源），建立最小访客身份（昵称 + 服务器临时 ID + 房间 + 连接状态 + 短期重连），迁移皮肤/披风/联机/P2P/云存档/界面；不得新建注册/登录；不得进入 phase-04；验收前不提交。
- 决策：
  1. **整文件删除，不做空壳保留**：`js/account.js`、`js/toy.js`、`js/cloudsave.js`、`js/checkin.js` 删除；`index.html` 脚本 88 → 85；不创建任何替代账号模块。
  2. **`GuestSession` 只做会话身份**：`js/guest.js` 负责昵称（`mcjs-guest-name`）、服务器临时 ID、房间 ID、连接状态、5 分钟 `sessionStorage` 重连提示；不包含注册、登录、密码、邮箱、手机号、永久账号或资料库。
  3. **服务端权威 ID**：`NetClient` 收到 `login.eid` 时调用 `GuestSession.connected(eid)`；未连接只暴露 `local_...` 占位并标记 `serverAssigned=false`。客户端不把昵称或本地随机 ID 当作已认证身份；phase-05 自建服务器必须签发并校验自己的临时 ID。
  4. **外观留在本设备**：保留 `mcjs-look`；删除账号外观接管与 `Account.update` 同步；衣柜锁定/签到分支删除；活动款装饰（企鹅/金苹果等）继续可用，不随签到删除。
  5. **多人保留房间能力**：昵称输入始终显示；邀请码、公开房间、直接连接、本地 P2P 房间保留；`hello`/`host`/`join` 不再发送账号 token；旧 `mcjs-room-key` 作为浏览器房间管理凭据保留到 phase-05。**房间所有权不能用昵称推断**（F-1）；phase-05 用服务端身份判断。
  6. **Toy 平台桥整体移除**：资料/关注/三连/内容检查/分享/二维码/容器模式/页面关闭由浏览器能力替代或删除；管理员聊天公告与旧房间服务轮询保留（与账号无关）。
  7. **不扩展范围**：`/api/skin` 正版皮肤查询、旧房间服务 403、K-41 末地问题不在本阶段处理；不改渲染/世界生成/红石。
  8. **流程**：留在 `develop` 工作区，不新建/切换/重置分支；不提交、不推送；验收通过后才提交，未通过按 ADR-009/§11.3 丢弃。
- 影响：
  - 账号、B站登录、识别码、关注/三连、管理员账号、冻结名单、Toy 诊断、云端存档、签到界面全部消失；旧 `mcjs-account`、`cloud` 元数据、`mcjs-cloud-dirty-*` 成为死数据（不自动清理）。
  - 多人界面改为昵称；`GuestSession` 成为昵称/会话 ID/连接状态的唯一入口。

## ADR-018 phase-05 自建服务器的技术形态与权威边界

- 日期：2026-11-12
- 背景：用户启动 phase-05，要求服务器运行在自己的 Windows 电脑上，不依赖 Bilibili 或其他游戏平台；
  服务器提供静态资源、房间、WebSocket、临时玩家 ID、邀请码、多人世界、状态同步、服务端存档、备份、
  状态监测、日志和正常启动/关闭；客户端负责渲染/摄像机/UI/输入/本地表现；不得新建账号系统。
- 决策：
  1. **零 npm 依赖的 Node 服务端**：`server/` 只用 Node 内置 `http`/`crypto`/`fs`，自写 RFC 6455
     WebSocket 服务端（`server/ws.mjs`）。ADR-011 允许 `ws` 是“唯一依赖”，但本项目选择不引入依赖，
     以保持解压即运行、Windows 一键启动；浏览器端使用标准 `WebSocket`。
  2. **不在服务器跑完整 `Game`/DOM/Canvas**：phase-00 已确认 `game.js` 的 `init/tick/render` 贯穿
     DOM/Canvas/WebGL/UI/音频；把完整无头游戏搬进服务器风险高。服务器只运行房间、身份、共享世界状态、
     同步、校验和存档。
  3. **服务器权威边界**：
     - 服务器权威：房间生命周期、邀请码、临时玩家 ID、会话令牌、房主/权限、方块覆盖层、方块实体、
       玩家实体状态（校验后接受）、掉落物实体、世界时间、服务器存档。
     - 客户端本地：WebGL2 渲染、摄像机、UI、输入、动画、地形确定性生成（服务器只存 seed + 覆盖层）、
       生物 AI、玩家物理/背包/生命、红石/流体/随机刻。
  4. **区块数据策略**：服务器保存 `seed + 方块覆盖层`，不传输/保存完整 98,304 格地形；客户端按相同 seed
     生成后应用覆盖层。加入时发一次完整增量（`welcome` + `blocks` 分批 + `blockEntities` + `items` + `ready`），
     之后只发 `b`/`be`/`E`/`env` 等增量。
  5. **基本权威校验而非完整反作弊**：移动速度/垂直速度/界内、方块距离/频率/合法 ID、协议结构/大小/频率、
     权限/成员/邀请码、聊天/名称清洗；超出拒绝/校正，不追求完整物理/战斗/物品语义权威。
  6. **客户端只上报玩家动作窗口内的方块改动**：包装 `Game.breakBlock`/`placeAt`/`useOnBlockItem` 设置短动作
     窗口，`World.setBlock` 只在该窗口且玩家附近时排队；避免把本地随机刻/流体/红石产生的全部改动上传。
  7. **范围**：不替换旧 `NetClient`/`RoomService`/`p2p`；不改渲染、世界生成、红石、战斗；不做公网/TLS/NAT；
     不做 phase-06 双存档管理。服务器不同步生物/红石/流体/战斗，作为本阶段明确边界记录。
  8. **实施补充（独立验收后）**：方块 ID 白名单展开游戏数据中的动态颜色/花朵表（1257 个，避免合法方块被拒）；
     客户端对已加载方块实体做差异上报；正常关闭先保存房间，再清理 HTTP 连接，避免 keep-alive 阻塞存档；
     掉落发送阈值收紧到 4.5（服务器 6），旧 socket 的 open/message/error/close 不覆盖新连接。
- 影响：
  - `index.html` 86 → 87 个脚本；`js/` 90 → 91 个 `.js`；新增 `server/`（9 个 `.mjs` + 配置/脚本/说明）。
  - 多人世界存档是“seed + 覆盖层”，世界生成版本变化会影响旧房间；已记录 K-73。
  - 多人对局里生物/红石/流体/战斗仍为各客户端本地结果；已记录 K-67/K-69。
  - 房间/身份/方块/玩家/物品/时间/存档由服务器维护；不再依赖旧房间服务。

## ADR-019 phase-05 临时身份、邀请码、权限与安全规则

- 日期：2026-11-12
- 背景：phase-03 已删除账号系统，`GuestSession` 只有昵称/临时 ID/房间/连接状态；旧 `login.eid` 来自旧房间
  服务，不能作为自建服务器的认证。phase-05 需要自己的房间/身份/权限/恢复规则。
- 决策：
  1. **无账号**：不新增注册/登录/密码/邮箱/手机号/永久身份数据库；昵称只是显示名，不是身份。
  2. **服务器签发临时玩家 ID**：`p_` + 16 hex；房间关闭/会话过期后失效；客户端不能用本地随机 ID 冒充。
  3. **会话令牌**：每次加入签发随机令牌（`crypto.randomBytes(32)`），只通过 `welcome` 发给本人；
     客户端存本标签页 `sessionStorage`；服务端只存 SHA-256。断线/刷新后 120 秒内可 `resume` 同一 ID，
     恢复 `pstate`；令牌不写日志，不属于账号。
  4. **邀请码**：8 位，字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去易混字符），用
     `crypto.randomInt` 生成；服务器保证当前/已存档房间唯一；不提供公开房间列表；加入/创建按 IP 限流。
  5. **昵称消歧**：同名在线玩家由服务器追加 `2..99`；权限/所有权不按昵称判断（解决 F-1/K-47）。
  6. **房主规则**：
     - 创建者为房主；房主可移出玩家、关闭房间。
     - 房主**短暂断线**保留房主身份，等待恢复窗口。
     - 房主**主动离开/被移出/恢复过期**时，房主转给最早加入的其他在线玩家；房间空则保留为“无房主”，
       下一位加入者成为房主。
     - 房主关闭房间：广播 `closed`、保存世界、`closed=true`、邀请码失效、从内存移除。
  7. **权限只由服务器会话决定**：忽略客户端传来的 `owner`/`admin`/`permission`；非成员不能发游戏消息。
  8. **安全**：静态白名单（不公开 `server/data`/配置/文档）；管理接口仅本机回环 + 令牌；WS 来源/大小/掩码/
     分片/心跳/错误次数；消息结构/类型/范围；方块/移动/聊天/方块实体/掉落限流；异常连接断开。
  9. **流程**：留在 `develop`，不新建/切换/重置分支；验收前不提交、不推送；未验收改动按 ADR-009/§11.3 处理。
- 影响：
  - `GuestSession` 继续作为昵称/连接状态来源；`MPClient` 把服务器 ID 交给 `GuestSession.connected`。
  - 旧 `mcjs-room-key`、旧 `login.eid`、旧房间服务不参与自建服务器权限；旧路径保留为遗留。
  - 客户端 `pstate`（背包/生命）只用于自己恢复，不作为其他玩家/战斗的权威（K-74）。
  - 真实局域网/公网/TLS 未做；HTTP 明文下邀请码/令牌可能被同网段嗅探（K-70）。
- 验证：见 `docs/phases/phase-05-server/TEST_REPORT.md`（服务端 62/62、E2E 18/18、单人 6/6、修复复核通过）。
- 状态：**已实施、已测试、修复复核完成；已验收（2026-11-12）；代码 `817bad3`；docs 收尾为当前 HEAD；已推送。**

## ADR-020 phase-06 双存档隔离、唯一 ID 与旧存档保护

- 日期：2026-11-12
- 背景：phase-05 已有单人 IndexedDB 和服务器每房 `world.json`，但客户端拦截只存在于 `mp.js`，
  `DB.listWorlds` 没有 `srv~` 过滤，世界 ID 仅按毫秒生成；服务器 `world.json` 能解析但结构无效时
  不会回退备份，恢复后也不写回。phase-06 要求两种世界明确分开、同名不覆盖、断线/刷新不删服务器世界、
  保护旧存档。
- 决策：
  1. **两套存储、两套 ID**：单人继续 `mc-js-clone` IndexedDB；服务器世界 `srv~<邀请码>` 只存
     `server/data/worlds/room-<code>/world.json`。数据库名/仓库/keyPath/区块编码不变。
  2. **唯一本地世界 ID**：`DB.newWorldId()` 使用 `w` + 时间戳 + 随机后缀 + 存在性检查；
     `Game.createWorld` 与 `anvil.js` 导入共用。同名世界不覆盖。
  3. **纵深防御**：`js/save.js` 自身对 `srv~` 做读/写/删/列表限制，不依赖 `mp.js` 的包装顺序；
     泄漏记录只隐藏不删除。`Game.saveWorld/quitToTitle/captureIcon` 对 `srv~` 跳过本地保存。
  4. **服务器恢复**：`loadAll` 对解析失败**和**结构无效都回退最新可读备份；恢复后原子写回；
     `dir` 必须与目录名一致，拒绝跨房装载。保留定时/关闭/异常保存与备份轮换。
  5. **旧存档保护**：不改格式、不做自动迁移；旧 `gen=1/2` 世界直接读取；旧云存档残留
     （`cloud`、`mcjs-cloud-dirty-*`、`mcjs-account`）不删除、不清理。
  6. **界面区分**：单人列表标注“仅保存在此浏览器”；服务器入口/创建/离开提示服务器保存，同名不覆盖。
- 理由：单人应离线可玩、服务器应权威且可恢复；不能因为同一名称、断线、刷新或加载顺序而互相覆盖/丢失。
- 影响：
  - 旧本地世界无需迁移；`srv~` 成为保留前缀（本地世界 ID 始终以 `w` 开头）。
  - 服务器世界不出现在单人列表；只能凭邀请码/继续房间进入。
  - 异常退出最多丢失 `autosaveSeconds` 内的改动；在线恢复备份没有 UI，需重启自动回退或手动复制。
  - 旧云存档无法安全迁移/恢复，保留为死数据（K-20/K-46/K-82）。
- 验证：服务端 22/22、浏览器 31/31、phase-05 回归 62/62 + 18/18 + 6/6；
  详见 `docs/phases/phase-06-dual-save/TEST_REPORT.md`。

## ADR-021 phase-07 性能预算、动态分辨率、画质建议与 20 TPS 调度

- 日期：2026-11-12
- 背景：phase-04/05/06 保留了完整 WebGL2 渲染与全部内容，但没有真实设备性能基线；实测发现
  Windows Node 的 50 ms `setInterval` 只有约 16 TPS；CPU 限速的无头 Chrome 会误报 `chunk stall`。
  用户要求优先 60/30 FPS、允许高档光影、不得删内容、不得伪造服务器达标。
- 决策：
  1. **性能结论必须带环境**：headless + 真实 GPU、SwiftShader、手机视口模拟分别标注，不得混写；
     真实手机未测则写 NOT TESTED。
  2. **优先用预算而不是删内容**：手机区块主线程上限 8 ms、桌面 12 ms；低/中档限制远距实体、地面阴影和
     瞬态粒子上限；高档保留全部；不删生物/建筑/光影档。
  3. **动态分辨率按实际帧时间**：用 1.5 s 窗口平均帧 + 迟到比例，先降 20% 再 10%；手机下限 0.4、桌面 0.5；
     显式帧率上限优先，否则默认 60 目标（不追 90/144 面板）。保留防抖与恢复。
  4. **画质建议可实测、可取消、不强制**：视频设置“测试性能并推荐画质…”复用 `QualityScreen` 的
     readPixels/GPU 完成时间；每个世界只在 12 s 后用实测 FPS/p95 提示一次，绝不自动改玩家设置。
  5. **内存**：解码后的 encoded chunk 记录立即释放；顶点 arena 手机 4 MB 页、桌面 8 MB；区块/实体/粒子
     预算按档位，不改变世界数据。
  6. **服务器 20 TPS 是调度问题，不是逻辑问题**：逻辑 tick 实测 0.14–0.60 ms；改用 10 ms 唤醒 + 50 ms
     到期补 tick（最多 3 个），暴露 `perf` 管理字段；公开接口隐藏 CPU/内存/tick 诊断。
  7. **K-39 只在“确实没有归属且管线空闲”时重请求**：有生成/装饰/完成/网格/存档读取进展时等待；
     SwiftShader + 8× CPU 限速下从 3 次误报/46 s 载入降到 0 次/约 9 s。
  8. **不伪造 20 TPS/60 FPS**：如果某设备/场景未达到，记录数字和瓶颈；不把模拟数据写成真机达标。
- 影响：
  - 低/中档在远距离会少画实体/地面阴影/粒子，这是画质分级的一部分；高档不变。
  - 动态分辨率会牺牲部分像素换稳定帧率；玩家可关闭。
  - 服务器 tick 现在可能一次补两个，逻辑时间仍按 50 ms/次推进；不会在一次长停顿后无限追帧。
  - 服务器公开状态不再包含 `stats`/`perf`；管理接口保留。
- 验证：见 `docs/phases/phase-07-performance/TEST_REPORT.md` 与 `docs/testing/performance-baseline.md`。
- 状态：**验收结束（2026-11-13）；代码 `508fcc8`、docs `a2bdb0e` 已推送 `origin/opusmc-integration`。**

## ADR-022 phase-08 先 LAN、再边缘 TLS、代理感知的管理边界

- 日期：2026-11-13
- 背景：phase-08 要求先让同一 Wi-Fi 的手机/电脑访问同一台服务器，再提供外网 HTTPS/WSS。
  服务器默认只绑定 `127.0.0.1`；一旦前面加 Caddy/Cloudflare Tunnel，源站 socket 会变成 `127.0.0.1`，
  原来的“管理接口只允许本机”会被绕过，所有远程玩家也会共用 `127.0.0.1` 的限流桶。
  本机没有公网 IPv4/域名；设计时没有第二台物理设备（后续 2026-11-14 用户用真实手机补测 LAN/蜂窝）。
- 决策：
  1. **安全默认不变**：`server/config.json` 的 `host` 仍是 `127.0.0.1`；LAN 必须显式
     `start-lan.bat` / `--lan` / 改配置。启动时优先选择有效私有 IPv4 作为主游戏地址，
     `127.0.0.1` 单独标为“仅本机访问”。
  2. **所有设备用同一个地址**：包括服务器电脑；邀请链接和 WebSocket 都取页面同源。
     不用 `127.0.0.1` 分享，避免链接在手机上打不开；邀请链接专项覆盖多次建房/刷新/恢复。
  3. **TLS 不写进 Node**：Node 继续零依赖，只做 HTTP/WS/房间/存档；HTTPS/WSS 由成熟组件终止：
     - **Cloudflare Tunnel：本阶段正式支持/验收的公网路径**（无需公网 IPv4/端口转发；
       quick tunnel 仅临时，命名隧道+域名长期）；
     - Caddy（有公网 IPv4 + 域名时的备用模板；自动 ACME；需要路由器 80/443 转发；
       未运行验证，不属于正式验收路径）。
  4. **代理身份只在“直连是本机回环”时可信**：`server/netutil.mjs` 解析 `X-Forwarded-For` 最后一项/
     `CF-Connecting-IP`/`X-Real-IP`；`clientIp()` 对 LAN 直连不信任转发头。
     管理接口要求“直连回环 + 转发地址回环”；WS 的 `conn.ip` 用真实客户端地址。
  5. **管理接口双层保护**：Caddyfile 对 `/api/admin/*` 直接 404；源站再做转发头校验 403。
     Tunnel 没有 Caddy 时，源站这一层仍能拒绝带正确令牌的远程请求。
  6. **不伪造部署完成**：本阶段不配置路由器端口转发、不申请域名/证书；Caddy 只作为备用模板，
     未运行验证，不写成正式验收通过。Quick Tunnel 的 URL 标临时，不作为长期地址。
  7. **防火墙脚本默认最小放行**：只放行 TCP 端口的专用网络入站；家用 Wi-Fi 被 Windows 标为
     Public 时需改专用或显式 `-IncludePublic`；不在公共 Wi-Fi 用。
- 影响：
  - LAN：`start-lan.bat`/`--lan` 绑定 `0.0.0.0`；主地址自动选择私有 IPv4，`127.0.0.1` 仅本机；
    `start-server.bat` 行为不变。
  - 远程：HTTPS 页面自动得到 `wss://`；管理接口/`server/data` 经公网不可达。
  - 同一 NAT/同一出口 IP 的玩家仍共享限流桶；隧道后按真实公网 IP 计（不是 `127.0.0.1`）。
  - `server/` 由 9 个 `.mjs` 变为 10 个（新增 `netutil.mjs`）；页面脚本/`js/` 数量不变。
- 验证（修复后）：LAN 主地址/127 标注 PASS；邀请链接一致性 8/8；LAN 协议 22/22、双浏览器 15/15；
  Cloudflare Tunnel 公网 HTTPS/WSS 协议 22/22、浏览器 15/15（前两次 quick tunnel 资产流超时，
  第三次通过）；外部节点 5/6 200；公网管理接口（含正确令牌）403；phase-05/06 回归全部 PASS。
  **真实手机 LAN（单人/移动/视角/放置/破坏/刷新）与手机蜂窝公网（HTTPS/进入/渲染/移动/视角/放置/破坏/刷新）
  由用户实测通过（2026-11-14）**；服务器日志有 LAN 与蜂窝客户端加入。用户未提供型号/网络/截图。
- 状态：**验收结束（真实设备用户实测）；代码 `ef8c540`；docs 收尾为当前 HEAD；未推送。**
  Caddy 备用模板/端口转发/防火墙脚本实际添加删除/长期公网/10 人仍 **NOT TESTED / BLOCKED**
  （K-95…K-100）；“PIN/邮箱验证”是 Cloudflare 外部流程，不是应用功能（K-100）。
