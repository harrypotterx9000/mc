# 技术决策记录（DECISIONS）

> 每条决策只增不改；被推翻时新增一条并注明取代关系。

## ADR-001 独立静态站点运行

- 日期：2026-11-06
- 决策：项目以静态站点方式运行（`index.html` + `js/`），本地用零依赖 Node 静态服务器，仅绑定 `127.0.0.1`。
- 理由：原游戏即 90 个脚本 + 数据文件，无构建步骤；静态服务满足 Worker/`fetch` 的同源要求。
- 影响：后续服务器只承担多人逻辑，不负责页面托管（可由同一进程提供，但不是必须）。

## ADR-002 移除 B 站重定向，保留原始版本标签

- 日期：2026-11-06
- 决策：为了让页面能在 B 站 iframe 之外启动，删除 `index.html` 中唯一一行 Toy 重定向脚本；其余字节不变。
- 理由：该脚本会把任何直接访问跳回 bilibili.com，导致本地不可用。
- 保护：删除前的完整源码提交为 `v0.0.0-original`，并另有 zip + SHA-256 清单。
- 影响：这是初始化阶段唯一的源码改动，已在 CHANGELOG 记录。

## ADR-003 无账号访客模式

- 日期：2026-11-06
- 决策：删除 B 站登录与账号体系；玩家用昵称 + 服务器分配的临时 ID；用邀请码进房间；不建任何注册/登录。
- 理由：见 PROJECT_SPEC §3/§6；避免永久身份带来的隐私与合规负担。
- 影响：云存档（按账号）取消；皮肤/披风改为直接开放；联机不再有解锁门槛。

## ADR-004 服务器权威 + 双存档

- 日期：2026-11-06
- 决策：多人世界由自建服务器模拟与存档；单人世界继续用浏览器 IndexedDB；两者互不覆盖。
- 理由：多人需要一致性与反作弊；单人应离线可玩。
- 影响：需要新增服务器世界实例与协议；客户端 `NetClient` 复用现有消息词汇。

## ADR-005 Git 导入与分支模型

- 日期：2026-11-06
- 决策：`main` 稳定、`develop` 集成、`phase/*` 阶段分支；初始化基线打 `v0.1.0-preproject`；原始源码打 `v0.0.0-original`。
- 理由：阶段化开发需要可回滚的清晰历史；原始版本必须可随时对照。
- 影响：合并需要用户确认；禁止强推与历史重写。

## ADR-006 按字节保存源码

- 日期：2026-11-06
- 决策：仓库设置 `core.autocrlf=false` 并加 `.gitattributes`（`* -text`）。
- 理由：原始 JS 为 LF；Windows 默认转换会让"原始字节"无法验证。
- 验证：`v0.0.0-original` 的 blob 与原文件 SHA-256 一致。

## ADR-007 远程仓库以远程现状为准

- 日期：2026-11-06
- 决策：`https://github.com/harrypotterx9000/mc` 当前只有 1 个 README 提交，与本地历史无关；首次推送采用**新分支 + PR**，不改远程 `main`，不允许强推。
- 理由：避免覆盖远程内容或制造不可逆历史。
- 状态：已执行（见 ADR-008）。

## ADR-008 首次远程推送采用新分支 + PR

- 日期：2026-11-06
- 背景：本地历史与远程 `main` 无共同祖先（远程仅 `6c476c0` README）。
- 决策：`git push -u origin main:opusmc-init`，远程新增 `opusmc-init` 分支；PR 由用户在 GitHub 上创建并合并；远程 `main` 在合并前保持不变。
- 结果：`opusmc-init` 已推送（`791d16b`），远程 `main` 仍为 `6c476c0`；GCM 已有可用凭据，未出现交互弹窗。
- 影响：本地 `main` 跟踪 `origin/opusmc-init`；PR 合并后需把 `origin/main` 拉回并重新对齐跟踪关系。


## ADR-009 未验收改动不保留

- 日期：2026-11-06
- 决策：阶段改动只有在用户明确验收通过后才提交；未验收的代码、文档、暂存区、stash、补丁与临时分支一律丢弃，不跨阶段保留。
- 背景：phase-01 的改动在用户指示"先不要开始阶段 1"后被整体丢弃（stash/补丁/临时目录/阶段分支全部删除）。
- 影响：后续阶段必须"实现 → 用户验收 → 提交"；不得用 stash 长期保存半成品。

## ADR-012 阶段 1 主菜单删减的实施边界

- 日期：2026-11-06
- 背景：用户启动 phase-01，要求删除首启两屏、公告面板、解锁披风/联机面板、选项三项、主菜单指定文字与反馈面板；同时要求不切换 Git 分支、不扩大范围。
- 决策：
  1. 首启两屏整体删除：`AgreementScreen`/`LEGAL`/`legalV` 与 `PlayerKindScreen`/`PLAYER_KINDS`/`playerKind` 不再保留；首启从画质设置开始。删除两屏后首启在 50 ms 内自动打开画质基准，会在标题世界尚未建好时做 `readPixels`；改为等待 `titleWorldReady()`（最多 8 s）后再打开，避免 SwiftShader/低端设备卡死。
  2. 新世界默认关教程（`meta.tutorial ?? -1`）；旧存档 `meta.tutorial` 保留。删除玩家类型后，小地图/死亡点默认改为仅显式开启时显示；情景提示 `settings.tips` 的值不受影响。
  3. 公告模块整体删除 `js/news.js`；签到与聊天里的管理员全服公告保留；签到按钮改用标题右上角固定位置。浏览器里旧的 `mcjs-news*` 键作为死数据保留，不自动删除。
  4. 删除 `UnlockScreen` 与所有入口（标题、账号、衣柜、锁定披风），并按 1-A 让 `onlineGate()` 直接放行；皮肤/披风的内部解锁数据保留到阶段 2 再统一开放。
  5. 选项「遥测数据」与 `TelemetryScreen` 删除；`Telemetry` 核心与 `GAME_BUILD` 按 ADR-011 暂留，因此阶段 1 没有 UI 关闭入口，记录为 K-27，阶段 3 随账号/原服务整体移除。
  6. 反馈整体删除：`FeedbackScreen`/`postFeedback`/`feedbackShot`/`FEEDBACK_KINDS` 与三处入口；`social.js` 的内容检查只保留 `ReportScreen`。举报功能保留。
  7. 主菜单指定文字删除；`OpusMC` 品牌字样保留。`index.html` 头部 Toy 性能上报内联脚本一并删除（阶段 0 的 K-03）。
  8. 本次按用户指令留在 `develop` 工作区，不创建/切换阶段分支、不提交；验收通过后再提交，验收不通过则按 ADR-009/§11.3 丢弃。
- 影响：
  - 阶段 2 仍需开放皮肤/披风/装饰，并处理管理员款与活动款时序。
  - 阶段 1 中未解锁的非活动款披风/正版皮肤暂时没有解锁路径（阶段 2 开放）。
  - 阶段 3 仍需删除账号、云存档、登录、公告接口、签到与 Toy（遥测已由 ADR-013 移除）。
  - 旧设置里的 `playerKind`/`legalV` 不再读取，保留为死数据。
- 状态：**已实施，独立验收通过；代码提交 `15154bd`**。
  > 注：第 5 项“保留 Telemetry 核心”已被 ADR-013 取代（K-27，2026-11-06）。

## ADR-014 phase-02 外观全开放与保存迁移

- 日期：2026-11-12
- 背景：用户启动 phase-02，明确要求“所有皮肤、披风和装饰不需要任何解锁条件（全开放包括 adm* 管理员披风）”，保留预览/切换/渲染/装饰选择/披风显示/保存恢复；多人入口不再要求登录/关注/三连/识别码，但房间仍需邀请码控制。用户同时要求不切换分支、不提前进入 phase-03、不扩大范围。
- 决策：
  1. **全部披风开放，包括管理员款**：`Capes.unlocked()` 只校验 id 已知；删除 `evOwned`、`Account.data.super`、`Account.has('anim'/'static')` 判定。本项**取代 ADR-011 第 3 项**（原“管理员款 adm* 保持隐藏”）与第 4 项中“活动款随活动删除”的当前阶段口径；活动款在 phase-02 直接可穿戴。
  2. **全部装饰开放**：`Cosmetics.owned()` 返回全部 id，`has()` 对已知 id 为 true，`lookOf()` 不再按账号拥有列表过滤帽子/宠物/前缀。
  3. **皮肤开放**：预设皮肤取消 `own` 过滤；正版玩家皮肤取消 `Account.has('skin')` 门槛；`Skins.lookOf()` 不再拦截 `m:`。
  4. **外观保存迁移到设备**：新增 `mcjs-look`（skin/slim/cape/hat/pet/pre）。无账号可保存并刷新恢复；登录时接管一次账号外观；有账号时保存仍同步 `Account.update({skin})`，失败保留本地。衣柜 `dirty` 用保存快照，不依赖账号。
  5. **账号模块保留但退出权限链**：删除登录后/每次访问的 `Account.checkUnlocks()` 调用；账号界面不再显示三连/关注状态与 gate；`Account.has()` 不再被外观调用。账号、登录、识别码、云存档、签到、Toy 的删除仍属 phase-03。
  6. **多人保持 1-A**：`onlineGate()` 直接放行；不在本阶段新增/修改房间协议、邀请码、公开房间列表或房间服务校验。
  7. **流程**：按用户约束留在 `develop` 工作区，不新建/切换/重置分支、不提交、不推送；验收通过后再提交。
- 影响：
  - `Capes`、`Cosmetics`、`Skins` 的账号拥有/解锁判断全部移除；只保留 id 有效性校验。
  - 新增 `mcjs-look`；旧账号 `data.skin` 仍兼容（登录时接管一次）。
  - 原房间服务可能仍按 `adm*` 校验或返回 403；客户端已开放，服务端问题留 phase-05。
  - phase-03 删除账号时需保留 `mcjs-look`，否则访客外观会丢失。
  - 活动款装饰在 phase-03 是否随签到删除需用户确认；当前全部开放。
- 验证：92 个 JS `node --check`；无头 Edge 27/27 自动检查通过；18 皮肤 + 23 披风（13 管理员 + 3 活动）+ 3 帽子 + 1 宠物 + 1 前缀全部可点/预览/渲染；游客保存刷新恢复；多人入口无登录门槛且邀请码控制保留；`game.errLog` 为空。详见 `docs/phases/phase-02-unlock-removal/TEST_REPORT.md`。
- 状态：**已实施、已测试、验收结束、已提交 `a9dc47b`；docs 收尾为当前 HEAD**。

## ADR-015 phase-03 彻底移除账号系统与访客身份

- 日期：2026-11-12
- 背景：用户启动 phase-03，明确要求彻底移除账号系统（`js_account.js`/`Account`、Bilibili 登录、Toy 身份、B 站 UID、关注/三连、解锁判断、账号 API/界面/绑定、账号云存档、相关资源），建立最小访客身份（昵称 + 服务器临时 ID + 房间 + 连接状态 + 短期重连），迁移皮肤/披风/联机/P2P/云存档/界面；不得新建注册/登录；不得进入 phase-04；验收前不提交。
- 决策：
  1. **整文件删除，不做空壳保留**：`js/account.js`、`js/toy.js`、`js/cloudsave.js`、`js/checkin.js` 删除；`index.html` 脚本 88 → 85；不创建任何替代账号模块。
  2. **`GuestSession` 只做会话身份**：`js/guest.js` 负责昵称（`mcjs-guest-name`）、服务器临时 ID、房间 ID、连接状态、5 分钟 `sessionStorage` 重连提示；不包含注册、登录、密码、邮箱、手机号、永久账号或资料库。
  3. **服务端权威 ID**：`NetClient` 收到 `login.eid` 时调用 `GuestSession.connected(eid)`；未连接只暴露 `local_...` 占位并标记 `serverAssigned=false`。客户端不把昵称或本地随机 ID 当作已认证身份；phase-05 自建服务器必须签发并校验自己的临时 ID。
  4. **外观留在本设备**：保留 `mcjs-look`；删除账号外观接管与 `Account.update` 同步；衣柜锁定/签到分支删除；活动款装饰（企鹅/金苹果等）继续可用，不随签到删除。
  5. **多人保留房间能力**：昵称输入始终显示；邀请码、公开房间、直接连接、本地 P2P 房间保留；`hello`/`host`/`join` 不再发送账号 token；旧 `mcjs-room-key` 作为浏览器房间管理凭据保留到 phase-05。**房间所有权不能用昵称推断**（F-1）；phase-05 用服务端身份判断。
  6. **Toy 平台桥整体移除**：资料/关注/三连/内容检查/分享/二维码/容器模式/页面关闭由浏览器能力替代或删除；管理员聊天公告与旧房间服务轮询保留（与账号无关）。
  7. **不扩展范围**：`/api/skin` 正版皮肤查询、旧房间服务 403、K-41 末地问题不在本阶段处理；不改渲染/世界生成/红石。
  8. **流程**：留在 `develop` 工作区，不新建/切换/重置分支；不提交、不推送；验收通过后才提交，未通过按 ADR-009/§11.3 丢弃。
- 影响：
  - 账号、B站登录、识别码、关注/三连、管理员账号、冻结名单、Toy 诊断、云端存档、签到界面全部消失；旧 `mcjs-account`、`cloud` 元数据、`mcjs-cloud-dirty-*` 成为死数据（不自动清理）。
